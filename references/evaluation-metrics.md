# Agent 评估指标体系

> 供 Phase 5 使用。原则：检索质量是 RAG 产品的瓶颈，不是模型能力；评测集先行，发版必回归。

## 目录

1. 指标分层
2. 各层指标定义与测量
3. 评测集设计
4. 回归与上线门槛

---

## 1. 指标分层

| 层 | 回答的问题 | 指标类别 |
|---|---|---|
| 任务层 | Agent 把事办成了吗 | 任务成功率、轮次效率 |
| 检索层 | 找回来的东西对吗 | 召回、重排质量、权限泄漏 |
| 生成层 | 答案对吗、可信吗 | 事实正确率、引用质量、拒答适当性 |
| 体验层 | 快吗、顺吗 | 延迟分位、首 token、打断率 |
| 成本层 | 赚钱吗 | 单次任务成本、缓存命中率 |
| 安全层 | 闯祸了吗 | 危险操作拦截率、注入成功率 |

## 2. 各层指标定义与测量

### 任务层

- **任务成功率**：人工或 LLM 评审判定"无需人工返工即可完成"。按场景与难度分层报告，不报总分。
- **轮次效率**：完成任务的中位工具调用轮次；轮次膨胀通常是检索质量或工具设计问题的信号。

### 检索层

- **Recall@K / MRR**：标准检索指标，按查询类型分层。
- **重排存活率**：过硬阈值后剩余候选比例；持续过高说明阈值失效，持续过低说明召回差。
- **重检索率**：触发二次检索的查询占比——检索质量的健康度代理指标。
- **权限泄漏率**（企业场景一票否决）：检索结果中出现无权访问内容的比例，目标为 0。

### 生成层

- **事实正确率**：答案中可验证事实的正确比例，人工抽检 + LLM 辅助。
- **引用质量**：引用密度（每百词引用数）、引用正确率（引用是否真支持该句）、引用点击率（用户视角的质量代理）。
- **拒答适当性**：证据不足时拒答是特性。同时监控"该拒未拒"（幻觉风险）与"不该拒而拒"（可用性损失）。

### 体验层

- 端到端延迟 P50/P95；首 token 延迟；长任务的进度可感知性（有无中间状态外露）。
- 打断率/修正率：用户中途纠正 Agent 的比例，反映"理解偏差成本"。

### 成本层

- **单次任务成本**：token 消耗 × 模型单价 + 工具/检索基础设施分摊。
- **缓存命中率**：prompt 前缀缓存命中比例，目标 80%+；每处时间戳抖动、工具顺序随机都是直接成本。
- 订阅产品额外跟踪：用量分布 vs 定价档位的匹配度（多少用户超额、多少浪费）。

### 安全层

- 危险操作（删除/外发/支付）拦截测试通过率，目标 100%。
- 提示注入红队测试成功率；工具输出消毒有效性。
- 金丝雀测试：注入假身份信息，检测系统 Prompt 泄露。

## 3. 评测集设计

- **规模**：200–500 条起步，覆盖全部核心场景 × 难度梯度（易 25% / 中 50% / 难 25%）。
- **来源**：真实用户日志脱敏 > 领域专家构造 > 合成数据。合成数据只作补充。
- **标注维度**：任务成功、事实正确、引用正确、拒答适当，逐条可判。
- **污染防控**：评测集不进训练/检索语料；定期换血防过拟合。
- **对抗子集**：单独维护注入攻击、越权访问、危险操作诱导三类对抗样本。

## 4. 回归与上线门槛

- 每次发版（模型更换、Prompt 修改、检索管道变更）必跑全量评测。
- 阻断规则：北极星指标跌幅超过阈值（建议 2–3%）或安全层任何一项失败，阻断发布。
- 线上灰度：按流量 1% → 10% → 全量，每档观察核心指标至少 24 小时。
- 建立"失败案例库"：线上 badcase 定期回流评测集，形成飞轮。
